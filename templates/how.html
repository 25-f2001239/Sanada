How it works

A recording goes in, a whole number comes out. Here is what happens in between.

The model reads a picture of sound

The audio is turned into a log-mel spectrogram: time runs left to right, pitch runs bottom to top, and brightness shows energy. Overlapping sources leave overlapping streaks in this picture, and the CNN learns to tell how many streaks belong to separate sources. The picture on the right is a decorative stand-in, not your audio.

Inside SourceCountCNN

Three convolution blocks learn the patterns, a pooling layer fixes the size, and two dense layers pick one count class.

Sliding-window voting

The server analyses an {{ status.clip_seconds|int }}-second clip as seven overlapping 2-second windows. Each window predicts a count. The most common prediction is reported. This animation uses made-up predictions to show the idea.

What to keep in mind

Counting is not separating

The model says how many sources are present. It does not produce a separate audio file for each one.

Long files are cropped

Only the central 8 seconds are analysed. Shorter files are padded with silence. The analyzer marks the analysed part on the waveform.

Confidence is not accuracy

The softmax score shows how decisive the network was, not whether it was right. Judge the model on a held-out test set.

This is a baseline

The research paper behind the dataset uses a Conformer regressor. This CNN is a lighter classifier that is easier to train and change.
